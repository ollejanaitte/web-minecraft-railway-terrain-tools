15. GUI Validation仕様
====================================================================
- run-validation-workflow.sh が正式GUI検証エントリ
- GUI_MODE=auto（DISPLAY有ならgui）/gui/headless で明示切替
- 検証専用profile: doc/testing/phase1_2_2/profiles/run-<RUNID>
- runtime/profiles/game・ユーザー通常Chromeには非干渉
- Chrome PID を起動時に記録、run単位でcleanup
- ビューポートを Emulation.setDeviceMetricsOverride(1208x505) で統一し、
  GUI/headless両モードで同一クリック座標を使用

16. headless fallback仕様
- GUI_MODE=headless で headless=new + swiftshader + CDP
- GUI標準・headlessは自動化/fallback用途
- headless特有対応: GuiScreenEditProfile通過 / screenshot 60s /
  tour timeout 900s（swiftshaderはHWより5-10倍遅い）

17. RUN ID仕様
- 形式: YYYYMMDD_HHMMSS（例 20260811_121433）
- 全ログ行に [RUNID] 表示、profile/SS/ログ名に付与

18. stage一覧（per-stage timeout）
- chrome_boot 30s / cdp_connect 20s / title_ready 90s /
  create_form 60s / world_join 240s / auto_validate 60s /
  tour GUI 300s・headless 900s / screenshot 20s / cleanup 15s
  （STAGE_TIMEOUT_SCALEで一律倍率可）

19. heartbeat仕様
- 12秒毎に [HEARTBEAT] stage/elapsed/autovalidate/tour/shots/screen/
  chrome_pid/retry を出力。動いていることが常に分かる。

20. stage timeout仕様
- 各stage個別timeout。超過時は stage/timeoutMs/lastScreen/
  autovalidate/tour/shots/chrome_pid/retry を記録して失敗。
- HUMAN_REQUIRED / STAGE_TIMEOUT は自動retryせず表面化。

21. retry仕様
- CREATE_RETRIES（既定3）でワールド作成を試行
- retry前は run単位で cleanupChrome + 再起動
- 同じ失敗は繰り返さない（menu bounce 2回でHUMAN_REQUIRED）
- ユーザーChromeは絶対にkillしない

====================================================================
22. Human Assist判定条件 / 23. HUMAN_REQUIREDフロー
====================================================================
22. 判定条件:
  - 同一stageで一定時間無進捗
  - 想定外GUI画面
  - click/inputの複数回失敗
  - menu bounceを繰り返す（2回でHUMAN_REQUIRED）
  - Chromeは生きているが画面遷移しない
  - 自動状態判定に確信が持てない
23. フロー:
  AUTO → 無進捗検出 → screen/log再確認 → 安全な自動復旧(少数回)
  → 改善しない → HUMAN_REQUIRED → Discord操作指示 → ユーザー操作
  → 検証再開（最大5分ポーリングで復帰を待機）

26. Vision Observer仕様

- モデル設定可能（VISION_MODEL env）:
