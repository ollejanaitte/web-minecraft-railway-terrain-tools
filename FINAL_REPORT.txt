Confirmed features:
  - RailGraph with RailNodes and RailSegments, persisted per-world via
    RailSystemSavedData (NBT key "rail_system")
  - Straight segments (RailSegmentType.STRAIGHT)
  - Cubic Bezier curve segments (RailSegmentType.CURVE, RailCurveData)
  - Slope and Switch segment types exist in enum but are not yet created
    by any command (placeholder enums only)
  - EntityRailVehicle: custom train entity, NOT minecart-based
    Entity name: "RailVehicle", ID: 201, spawn type: 80
  - VehicleType enum: DEFAULT, EXPRESS, FREIGHT (visual color differences
    in RenderRailVehicle)
  - Train formations: carIndex, trainId, trainLength, carSpacing (in blocks),
    isLeadCar, forward
  - Lead car reads rider input (W/S forward/back throttle)
  - Follower cars sync to lead car every tick, maintain block-distance
    spacing using segment.getLength()
  - Segment transition: at node endpoints, searches connected segments;
    switch target priority > route target > first found
  - Switch routing: /railsys switch sets preferred outgoing segment
  - Station system: /railsys station marks nearest node; trains stop for
    60 ticks (~3 seconds) on arrival, then resume
  - Route targeting: /railsys route sets target node; train chooses segments
    that move closer (not full A* pathfinding)
  - Occupancy tracking: prevents two trains on same segment (runtime only,
    not saved to NBT)
  - Debug markers: gold block (start node), diamond block (end node),
    emerald block (Bezier control 1), redstone block (Bezier control 2),
    lapis block (station), stone (intermediate), rail (track path)
  - HUD: when riding vehicle, shows RailVehicle, speed, target, trainId
  - RailWand (item 433, "rail_wand"): 4-point Bezier curve creation
    Left/right-click to place points; sneak+click to clear
  - DataWatcher: 9 fields synced (trainId, carIndex, trainLength,
    carSpacing, isLeadCar, targetSpeed, speed, segmentId, progress)
  - NBT save/load: 14 NBT keys preserved

Confirmed commands (WorldEdit-style):
  /pos1           - Set selection position 1 to player position
  /pos2           - Set selection position 2 to player position
  /copy           - Copy selection to clipboard
  /paste          - Paste clipboard at player position
  /clear          - Fill selection with air
  /fill [block] [meta] - Fill selection with block (or block being looked at)
  /undo           - Revert last operation
  /wand           - Give wooden axe selection wand
  /desel          - Clear selection points
  /wehelp         - Print all commands and workflow
  /preview <axis> <blocks>    - Set paste preview offset
  /pastepreview   - Paste at preview position
  /previewclear   - Clear preview
  /offset <axis> <blocks>     - Nudge preview position
  /offsetreset    - Reset preview to player position
  /stack <axis> <count>       - Stack clipboard along axis

Confirmed features:
  - Wand: vanilla wooden axe
    Left-click (destroy block): sets pos1
    Right-click (use block): sets pos2
  - /weui opens GuiWorldEdit client-side GUI
    Button sections: Selection, Clipboard, Preview, Transform, Fill, Step, Close
  - Selection wireframe: FIREWORKS_SPARK particles, every 10 ticks
  - Paste preview wireframe: REDSTONE particles, every 10 ticks
  - Wireframe auto-spacing to keep under 600 particles
  - Background jobs: paste, fill, clear, undo, stack run async
    4096 blocks per tick
    Progress reported every 10 ticks with text progress bar
    Only one job per player at a time
  - Maximum selection size: 64x64x64 = 262,144 blocks
  - Copy stores blocks relative to player position at copy time
  - Preview/offset/stack support x, y, z axes
  - Tick: CommandWorldEdit.tick() called from MinecraftServer.server tick
