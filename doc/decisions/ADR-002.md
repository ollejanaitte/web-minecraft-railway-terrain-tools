# ADR-002: Rail Geometry vs Rail Network Separation
Status: Accepted (Phase -1)
## Context
v1 RailGraph mixes geometry (segments) with routing (switch/route/occupancy)
and persistence. RTM keeps per-piece geometry (RailMap) with routing implicit
[REFERENCE-IMPLEMENTATION].
## Decision
Separate: RailGeometry (pure shape, immutable) vs RailNetwork (pieces
registry + node adjacency + routes + signals/stations). RailPiece binds
geometry to world state. RailPath records actual traversal.
## Alternatives
- Single unified object (v1) - rejected: couples concerns, blocks
  distance resolver and route history.
## Pros
Clean ownership; geometry reusable; route history enables follower
continuity; testable in isolation.
## Cons
More classes (managed by package layering).
## Risks
Interface churn if geometry evolves; mitigated by Phase 1 stabilization.
## Consequences
v1 RailGraph migrates to RailNetwork (routing layer); RailSegment to
RailPiece/RailGeometry.
