# ADR-005: Content / ModelPack Strategy
Status: Accepted (Phase -1)
## Context
RTM core/content split; ModelPacks define vehicles/rails/signals etc.
[C-MP]. v2 must add content without core changes.
## Decision
ContentDefinition system: immutable definitions (Train/Rail/Signal/Machine/
Wire/Object/Sound/Animation/Script) loaded from packs (Model*.json +
pack.json + sounds.json). JSON uses RTM-compatible field names where
possible, aliases for legacy, v2 additions namespaced. Registry by defId;
missing def -> dummy fallback.
## Alternatives
- Hard-code all types - rejected (no ecosystem).
- Full RTM pack compatibility import - future, license-gated.
## Pros
Extensibility; parity path; clean.
## Cons
Schema management effort.
## Risks
Pack name collisions (version precedence); malformed content (validated).
## Consequences
Runtime depends on definitions; converter pipeline (Phase 8).
