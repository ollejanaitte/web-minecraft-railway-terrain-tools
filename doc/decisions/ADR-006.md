# ADR-006: Script Strategy
Status: Accepted (Phase -1)
## Context
RTM supports JavaScript (renderer/sound/server/gui) [C-MP]. Browser/TeaVM
is single-thread; full JS is a security, determinism, and performance risk.
## Decision
RESTRICTED scripting, not full JS: an expression/state layer with a fixed
allow-listed API (speed/notch/door/signal/time/part transforms), plus
declarative animation triggers. Optional WebWorker-based client-only
visual scripts in a later phase; server scripts strictly validated.
## Alternatives
- Full JS (Nashorn-like) - rejected: freeze risk, remote-exec risk,
  non-determinism.
- No scripts - rejected: loses RTM content power.
## Pros
Safe, deterministic, fast, browser-feasible.
## Cons
Content authors lose full-JS freedom (documented; restricted DSL).
## Risks
Coverage gaps for exotic packs; mitigated by declarative triggers + hooks.
## Consequences
ScriptDefinition describes restricted hooks; server validates.
