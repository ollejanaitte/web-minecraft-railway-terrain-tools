20. BOX renderer設計
    SingleBoxProofRenderer (validation-only):
      - 独立3D geometry (Tessellator/WorldRenderer POSITION_COLOR)
      - setBlockしない / Entity不要 / texture不要
      - world座標に固定、camera-relative translate
      - singleboxワールドのみ (クライアント記録ワールド名でgate)
      - 6面直方体・単色

21. BOX寸法
    Length = 0.50 m (X) / Width = 0.30 m (Z) / Height = 0.20 m (Y)
    1ブロック(1m)より十分小さい。

22. BOX world座標
    origin (299.75, 4.00, 299.85)〜(300.25, 4.20, 300.15)
    center (300.0, 4.10, 300.0) / ground top y=4.0 (底面が接する)

23. camera-relative処理
    camX/Y/Z = viewEntityの補間位置 (lastTickPos + (pos-lastTickPos)*partial)
    GlStateManager.translate(BOX_CX-camX, BOX_CY-camY, BOX_CZ-camZ) で
    ワールド座標に固定。カメラ移動してもズレない（SS-02..04で検証）。

STEP 3001 - CP-R1-01/02 Initial Audit + Renderer Audit
  開始SHA c6c77c2c。既存STEP1/2にSingleBoxProofRenderer等が実装済み。
  render hookは EntityRenderer.renderWorldPass(pass==0) に配置されていた。

STEP 3002 - CP-R1-03 原因特定1: pass==0では通常描画で発火しない
  renderWorld() の通常パスは renderWorldPass(2) を呼ぶ
  (pass==0はアナグリフ時のみ)。→ EntityRenderer を pass==0||pass==2 に修正。
  実ゲームで [SINGLEBOX] render ... 出力を確認 → render hook発火YES。

STEP 3003 - CP-R1-04 原因特定2: クライアントワールド名がMpServer
  WorldClient.java:81 が常にワールド名 "MpServer" を設定。
  'singlebox' 判定が常に false。さらに統合サーバーは Web Worker で
  別スレッドのため static (validationEnabled) も共有されない。
  → Minecraft.launchIntegratedServer() でワールド名をクライアント側static
     (SingleBoxProofValidation.setClientWorldName) に保存し、
     SingleBoxProofRenderer が getClientWorldName() を参照するよう修正。
  → 実ゲームで gate=true、'SINGLEBOX render hook FIRED (gate=true)' を確認。

STEP 3004 - CP-R1-05/06 Clean Scene + GUI First Proof + Screenshot
  Clean Scene: cleanflat/singlebox に village-free preset "2;7,3,3,2;1;"
  を適用（村の家がBOX視界を塞ぐ問題を回避）。
  GUI検証 (RUN r5a_2045):
    SS-01 CLEAN_SCENE 平坦な草地面のみ (Vision PASS)
    SS-02 BOX_FRONT   BOX 35x23px (Vision PASS conf 0.99)
    SS-03 BOX_DIAGONAL BOX 32x23px (Vision PASS)
    SS-04 BOX_FAR     BOX 17x11px (Vision PASS)
  ピクセル解析: BOX色(255,60,40) をworld領域(y<425)で検出。
  カメラ距離に応じたBOXサイズ変化 = ワールド座標固定の3D描画を確認。
